# わくわく花火工房

公開版（https://mohs-code-web.pages.dev/）の挙動と配布アーカイブを確認するための作業フォルダです。

## 公開・更新方法

- 公開URL: [https://hinyari-sweets-workshop.pages.dev/](https://hinyari-sweets-workshop.pages.dev/)
- ソース: [gakugaku3333/hinyari-sweets-workshop](https://github.com/gakugaku3333/hinyari-sweets-workshop)
- Cloudflare PagesはGitHubの`main`ブランチと連携済み。`main`へ反映すると自動で公開版も更新される。

### 更新の手順

1. このフォルダ内の`index.html`、`sw.js`、`manifest.webmanifest`、または`assets/`を編集する。
2. 変更をGitHubリポジトリの`main`へコミット・pushする。
3. Cloudflare Pagesが自動デプロイを完了したあと、上の公開URLで表示を確認する。

**注意:** キャッシュされるファイルを更新したら、`sw.js`の`CACHE_NAME`を新しい値に変える。これにより、すでにホーム画面へ追加したiPhoneでも最新の画像・画面を取得しやすくなる。

## 現状の把握（2026-08-17）

- 子ども向けの縦画面（9:16）「2048」型パズル。スワイプで4×4盤面の鉱物カードを動かし、同じカードを合体させてモース硬度10のダイヤモンドを目指す。
- 起動順は「タイトル／自動デモ」→「あそびかた」→「ゲーム」。ゲーム中はダブルタップでポーズメニューを開く。
- Web版は Python + pygame を Pygbag（WebAssembly）で動かす構成。配布物は `mohs_code.apk`（約1.4 MB）で、ゲーム本体・画像・フォント・効果音を同梱する。
- 実機相当の初回ロード、遊び方画面への遷移、開始、右スワイプ後のカード移動と1枚追加を確認済み。

## 良い点

- 鉱物の名称・硬度・イラストがカードにまとまり、学習テーマがゲームルールに自然に接続している。
- タイトル、星空、木箱、鉱物のビジュアルに一貫性がある。
- スワイプごとに1枚追加、同じ値で合体というルールが分かりやすい。
- モバイル向けにタッチ操作、Web Audio、描画負荷の削減まで実装されている。

## 改良候補（優先順）

1. **初回起動の待ち時間を短く、予測可能にする**
   - Python/WASMランタイム・pygame・アーカイブを段階的に読み込むため、初回は待ち時間が発生する。
   - ローダーに「残り時間の目安」「現在の段階」、再訪時の即時開始を加え、可能ならゲームをネイティブWeb実装へ置き換える。

2. **横長画面の利用体験を整える**
   - 16:9のPC表示では、縦長ゲームが中央に小さく表示され、左右に大きな余白が生じる。
   - 縦向き利用の案内、PC用の横レイアウト（遊び方・鉱物図鑑・ランキングを左右余白に表示）、またはフルスクリーン導線を検討する。

3. **ルール理解を視覚的に補助する**
   - 遊び方は文章中心。最初の一手で矢印／手のアニメーションを重ね、「同じカードが合体する」短い例を見せると就学前〜低学年でも入りやすい。

4. **プレイ中の目標と達成感を強める**
   - 現状は経過時間が主表示で、現在の最高硬度・次に作れる鉱物・進捗が即座には分かりにくい。
   - 最高硬度バッジ、次の鉱物プレビュー、合体時の名称読み上げ／豆知識、硬度10までの進捗表示が候補。

5. **アクセシビリティと操作の逃げ道を用意する**
   - スワイプ専用ではなく、画面上の4方向ボタン、キーボード操作の明示、音量・音のON/OFFを通常メニューへ追加する。
   - 色だけに頼らず、カードの番号・名称を維持する現在の方針は良いので、文字サイズ切替も検討する。

6. **計測と継続改善の基盤を加える**
   - ロード完了率、遊び方離脱、初回ゲーム開始、最高硬度、ゲームオーバーまでの手数を匿名で計測できると、改善の優先順位を実データで決められる。

## 試作

`index.html` は、外部ライブラリ不要でブラウザから開ける操作可能な試作版。
4×4盤面、スワイプ／矢印キー操作、合体、カード追加、ゴール・ゲームオーバー判定、進捗表示、リスタートを実装している。

背景には生成イラスト [`assets/fireworks-festival-bg.png`](assets/fireworks-festival-bg.png) を使用。夜空に色とりどりの花火を配しつつ、ゲーム盤面のため中央は読みやすく抑えた構図としている。

カードは各段階の花火が見分けやすいよう、生成した個別イラストで表現している。`assets/card-01.png` から `assets/card-10.png` は、段階表の順に対応する。

## iPhone / PWA 対応

- `manifest.webmanifest` — ホーム画面名、アプリ表示、テーマ色、アイコンを定義。
- `assets/apple-touch-icon.png` — iPhoneのホーム画面用アイコン（180×180）。
- `index.html` のスプラッシュ画面 — 起動直後に表示される工房のローディング画面。
- `sw.js` — 本体・背景・10枚のカード画像を初回アクセス時にキャッシュし、以後はオフラインでも起動可能にする。

Service WorkerはHTTPS（Cloudflare Pagesなど）で公開したあとに有効になる。iPhoneのSafariで公開URLを開き、共有メニューから「ホーム画面に追加」を選ぶ。
